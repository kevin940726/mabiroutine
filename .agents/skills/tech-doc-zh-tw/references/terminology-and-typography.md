# 術語與排版

僅在需要處理術語、錯詞、標點、留白或大小寫時讀取本檔案。所有規則只作用於可見正文，不作用於程式碼、路徑、欄位、命令、設定項和使用者指定的固定字面量。

## 術語原則

- 同一概念使用同一首選術語。
- 優先採用目標專案術語表和產品官方寫法。
- 不因為追求詞彙變化而替換同義詞。
- 詞語可能有多個合法含義時，先判斷語境，不做全域性替換。
- 專案專屬術語放在目標專案的覆蓋檔案中。

## 空泛表達與黑話

以下詞語容易掩蓋具體動作。只有在有明確業務定義、屬於正式術語、引用原文或使用者要求保留時才使用：

- `賦能`
- `抓手`
- `閉環`
- `沉澱`
- `對齊`
- `對標`
- `拉通`
- `打通`
- `協同`
- `聯動`
- `洞察`
- `賽道`
- `心智`
- `調性`
- `戰役`
- `鏈路`
- `勢能`
- `兜底`
- `落盤`
- `收口`
- `透傳`

優先說明它實際指什麼：

- `賦能` -> `提供`，或直接寫提供的能力
- `抓手` -> `關鍵措施`
- `閉環` -> `完整流程`，或列出開始、處理和完成條件
- `沉澱` -> `形成`、`累積`、`儲存`
- `對齊` -> `統一`、`確認一致`
- `拉通` / `打通` -> `連線`、`貫通`
- `洞察` -> `分析結論`
- `兜底` -> 寫出失敗後的具體保障機制
- `落盤` -> `寫入檔案`、`儲存到本地`
- `透傳` -> `原樣傳給下游`

以下詞語需依語境判斷，不應由檢查工具自動替換：

- `場景`

- `觸點`
- `卡點`
- `佈局`
- `矩陣`
- `顆粒度`
- `復盤`
- `梳理`
- `輸出`
- `提煉`

保留內部術語時，在首次出現處說明實際含義，避免連續堆疊多個術語。

## 標點

- 中文正文預設使用全形中文標點。
- 中文引號使用直角引號 `「」`，巢狀引用使用 `『』`；專案、地區、出版或固定引用規範可以覆蓋。
- 中文全形標點前後不額外加空格；英文句子和程式碼遵循各自規則。
- 中文說明使用全形括號 `（）`，括號內側不留空格。英文原文、程式碼和函式呼叫中的括號保持原樣。
- 文件、書籍等作品名稱使用書名號 `《》`；按鈕、選單和欄位展示名使用 `「」`。機器可讀欄位名使用行內程式碼並保持原樣。
- 中文省略號使用 `……`，破折號使用 `——`；不以三個英文句點或連續連字號代替。程式碼、命令選項和 Markdown 結構標記保持原樣。
- 避免連續驚嘆號、省略號和口號式斷句。
- 完整句式的列表項統一使用句號；短語型列表項可以不加句號，但同一列表保持一致。
- 並列詞語使用頓號，並列分句根據層級使用逗號或分號。
- 冒號後應當確有解釋、列舉或引用，不要把每句話都拆成冒號列表。
- 破折號、括號和斜線只在關係明確時使用，不用它們代替句子組織。

以下反例僅針對可編輯的中文正文，不要求修改固定引用或程式碼原文：

| 不推薦寫法 | 推薦寫法 |
| --- | --- |
| `點選“儲存”按鈕。` | `點選「儲存」按鈕。` |
| `提示為「請選擇「儲存」」。` | `提示為「請選擇『儲存』」。` |
| `應用程式介面( API )` | `應用程式介面（API）` |
| `參見「安裝指南」。` | `參見《安裝指南》。` |
| `支援 API 、 SDK 和命令列 。` | `支援 API、SDK 和命令列。` |
| `正在載入...` | `正在載入……` |
| `檢查結果--連線失敗。` | `檢查結果——連線失敗。` |

## 稱呼

- 技術文件預設不直接稱呼讀者，優先使用無主句或明確角色。
- 根據語境使用 `開發者`、`技術負責人`、`實作人員`、`業務負責人`、`產品經理`。
- `你`、`您`、`同學` 屬於風格提示，不是普遍語言錯誤；消費產品、說明文字或品牌規範可以允許第二人稱。

## 中文與英文、數字之間的留白

在可見正文中，中文與英文單詞、英文縮寫、阿拉伯數字和版本號之間加一個普通半形空格（U+0020），即「盤古之白」。不是半個空格，也不使用全形空格、連續空格或 Tab 模擬對齊。Markdown 縮排、表格結構和行尾兩個空格表示的顯式換行除外。

| 不推薦寫法 | 推薦寫法 |
| --- | --- |
| `使用API取得資料` | `使用 API 取得資料` |
| `等待3秒` | `等待 3 秒` |
| `版本2.0已發佈` | `版本 2.0 已發佈` |
| `增長50%` | `增長 50%` |
| `使用  API 取得資料` | `使用 API 取得資料` |

中文與行內程式碼之間加一個半形空格，只調整程式碼標記外側，不修改程式碼內部。例如：

- 不推薦：``執行`npm install`安裝相依套件。``
- 推薦：``執行 `npm install` 安裝相依套件。``
- 行內程式碼緊鄰中文標點時不加空格，例如：``執行 `npm install`。``

連結按顯示文字判斷邊界，不在連結語法內部插入排版空格，也不修改目標位址。例如：

- 不推薦：`參見[API](https://example.com)說明。`
- 推薦：`參見 [API](https://example.com) 說明。`
- 中文連結文字不額外留白：`參見[安裝說明](https://example.com)。`

以上規則服從目標專案約定，不對以下內容內部做機械替換：

- 行內程式碼和程式碼塊
- JSON 鍵名
- URL 和 API 路徑
- 資料庫欄位名
- 命令、設定項、佔位符號和正規表示式
- 直接沿用介面定義的表頭
- 產品官方拼寫和使用者指定字面量

## 數字、單位與日期

- 數字與半形單位符號之間加一個半形空格，例如 `10 GB`、`200 ms`、`25 °C`。
- 百分號和角度符號緊鄰數字，例如 `50%`、`90°`；溫度單位 `°C` 與角度符號 `°` 不同。
- 中文與完整數值之間留白，不拆開數值內部結構，例如 `增長 50%`、`旋轉 90° 後停止`、`溫度為 25 °C`。
- 負號、小數點、千位分隔符與數字之間不加空格。已有數值和精度保持不變，不為排版擅自換算單位或增減小數位。
- 普通中文中的數值範圍優先使用 `至`，例如 `3 至 5 天`；保持原有上下界和包含關係，程式碼中的連線符不變。
- 中文日期寫作 `2026 年 9 月 29 日`，中文時間寫作 `下午 3 點`；數字時間內部不加空格，例如 `15:30`。
- 面向跨時區讀者時註明已知時區；缺失時提示補充，不根據所在地猜測。英文日期遵循目標地區規範，有歧義的純數字日期不自動轉換。

| 不推薦寫法 | 推薦寫法 |
| --- | --- |
| `容量為10GB` | `容量為 10 GB` |
| `耗時200ms` | `耗時 200 ms` |
| `增長 50 %` | `增長 50%` |
| `旋轉 90 °` | `旋轉 90°` |
| `溫度為25°C` | `溫度為 25 °C` |
| `偏移為 - 3.5` | `偏移為 -3.5` |
| `2026年9月29日` | `2026 年 9 月 29 日` |
| `15 : 30` | `15:30` |

數字排版還應檢查：

- 日期、時間和時區是否完整
- 百分比與百分點是否混用
- 數值是否帶有必要單位
- 區間上下界和包含關係是否明確
- 貨幣、溫度、儲存單位和千位分隔是否一致

## 段落換行與原始檔行寬

中文 Markdown 段落在原始檔中保持一段一行，不為了控制原始碼行寬在段落中間手動斷行。長行交給編輯器軟換行閱讀。

取消硬換行的原因：

- 段落被手動斷成多行後，原始檔很碎，改寫、比對和審閱都更難對照上下文。
- 軟換行在多數渲染器中按空格處理，中文與英文邊界上的斷行會多出或吞掉空格。

保持一段一行的範圍：

- 正文段落
- 列表項正文；列表層級、標記和縮排不變

以下內容保留原有換行：

- 圍欄程式碼塊和縮排程式碼塊，包括寫在列表標記之後的圍欄和列表項內的縮排程式碼
- 表格的行結構
- 標題、Setext 下劃線、分隔線和連結引用定義
- HTML 塊按整塊保留，包括多行 `<pre>` 和多行註釋
- 引用塊，它可能需要保持原文形態
- 行尾兩個空格或反斜槓表示的顯式換行

展開硬換行後，逐處複查拼接邊界的留白：

- 中文與中文之間不加空格
- 中文與半形英文、數字之間加一個空格，例如 `作為 ASR`、`的 stdio 模式`
- 全形標點兩側不加空格，例如 `說明，API 返回`
- 行內程式碼、連結和強調標記按可見文字判斷，例如 `詳見 **介面說明**文件`

以下寫法需依語境判斷，只能提示人工確認：

## 高頻錯詞與語境詞

可以作為確定錯誤處理：

- `閥值` -> `閾值`
- `佈署` -> `部署`
- `反回` -> `返回`
- `回朔` -> `回溯`
- `做為` -> `作為`
- `embeding` -> `embedding`
- `提示工程學` -> `提示工程`

必須結合語境判斷：

- `登入系統`，但可以說 `登陸月球`
- `配置參數`，但可以說 `配製溶液`
- `截至 4 月 12 日`，但可以說 `截止日期`
- `啟用功能`，但可以說 `起用新人`
- `標識欄位`，但可以說 `在圖中標示位置`
- 技術能力通常寫 `即時通訊`，但 `即時` 在其他語境中可能正確
- `認證` 表示確認身份，`授權` 表示授予權限

## 數量與邏輯

- `縮小了 3 倍` -> `縮小到原來的 1/3` 或寫明減少比例
- `從 20% 增長到 30%`：增加 10 個百分點，相對增長 50%
- `轉化率提升了 5%`：確認是提升 5% 還是 5 個百分點
- `翻了 1 倍` -> `變為原來的 2 倍`
- `不超過 100 以上` -> `不超過 100`
- `預計大約在 3 點左右` -> `預計 3 點左右`

修正表達時不得自行補充原文沒有的基數、年份、期限或測量結果。
