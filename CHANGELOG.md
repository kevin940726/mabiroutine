# Changelog

Reader-facing log of user-visible changes. Newest first. One section per release (a push to `main` deploys to prod); the top `Unreleased` section holds work not yet pushed and gets a date + label when it ships.

## Unreleased

### Features
- Finishing a section now pops a small emoji celebration: the moment 每日任務 / 每週任務 (per character) or 帳號共通 (shared) goes all-done, its own task icons burst at the tap that finished it — the puff is the section's visible rows, so hidden rows sit it out. Edge taps fire up-inward so the burst stays on screen. Only row controls can fire it — the check runs inside the tap/drag/keypress handler itself, so background sync, imports and resets never celebrate. It stands down under `prefers-reduced-motion`, and a reset re-arms it by dropping the section below all-done
- Tapping a tracker row's portrait now deep-links to that row's NPC shop and flashes the row, with a 返回任務追蹤 chip for the way back. A regular trade row's face, a pinned-group parent's face and a group child's item icon are all buttons now (hover brightens first, so the affordance states itself before the click); a parent flashes every child at once. Every jump lands on that merchant's FULL section — town, search, 優先度 and 類型 all reset, so the target can never hide behind a stale filter — and the way back restores the tracker's scroll position. The URL names the landing (`?npc=&item=` plus origin), so a copied link lands identically on a cold load, including its way back. Faceless rows (custom tasks, the icon fallback, pins grouped under 其他 with no merchant) stay inert: with no shop section to land on there is nothing to link to
- A pinned row now stays visible in the shop under any 優先度 filter, so the default 必換+推薦 view is pins ∪ those two tiers. The catalog opens on 必換+推薦 (39 of 194) to keep the flood down, but a pinned 一般 (neither 必換 nor 推薦) row was hidden by that default the moment you pinned it — pinning something and then not seeing it is a broken promise. Pins are a deliberate act, so the priority filter no longer hides one; the other filters (城鎮 / NPC / 類型 / search) still apply to it, since those are things the user set by hand and honoring them keeps the row in the context it was found in. Measured: with `tir-f1` (視需求) pinned it is present in the 40-row default view while its unpinned twin `tir-f2` is absent, and both appear once the filter widens to all 194 rows. A non-empty search suspends the priority filter instead of composing with it: typed text names what the user wants, while the ticked tiers are usually a starting view they never chose — searching 糖 with one 糖 row pinned used to return just that pin, hiding the other NPCs selling it behind 必換+推薦 with no way out in sight, and now returns all three. The rule: explicit input overrides the app's implicit default, never an explicit choice, so town / NPC / kind still narrow a search and the ticks resume untouched when the query clears; the section count discloses the suspension (`搜尋時顯示所有優先度`) exactly while it holds. Pins lead their section in pinning order with the tier order (`compareRows`) kept below them, and sections themselves follow the canonical town order (`TOWN_ORDER`, game-region order) rather than first appearance — sorting pins first globally used to drag a pinned town's whole section to the top, so a 糖 search read 地下城 first instead of 堤爾克那. The bypass stays stated too (`含 1 筆已釘選，不受優先度篩選`) exactly when the trigger reads 必換、推薦 while the list holds other tiers, so the exception is visible rather than silent
- The section headers dropped their 收合 / 展開 text: the chevron already shows the state, the whole bar is the click target with a hover fill, and the label was a third signal for the same thing that only appeared from `sm` up (mobile never had it). The disclosure now reports itself the way a control should — the toggle carries `aria-expanded`, which it did not before, so a screen reader hears whether the section is open instead of only hearing its title and count. A collapsed section still spells the way back out (已收合 — 點擊上方展開)
- Adding a custom task now happens per section: each of 每日任務 / 每週任務 / 帳號共通 carries its own 新增 in its header, and the dialog opens already set to that section, so the task lands where you clicked instead of in a dropdown you have to change. A focused search field is the one exception that outranks the rule: narrowing the list shortens the page, the browser clamps the scroll back up, and without the exception the pill (and the field being typed in) vanished mid-word; blur restores the rule immediately. The whole surface calls the state 釘選 the way the store (`barterPins`) and the tracker already did — it was 已選 here and a shopping bag, a third vocabulary for one concept

### Fixes
- Shop tiles keep their bands aligned on phones: the name band now always reserves two lines below `sm`, since at two ~158px columns even medium names wrap and a one-line tile sat its icon and cost a line above its two-line neighbour. The 4-column container-query reservation is unchanged, and between the two every name fits one line so nothing is reserved there
- iOS no longer zooms when any text field takes focus: the earlier 16px base on `Input`/`Textarea` was overridden back down to 12–14px at six call sites (the two header rename pills, the sync link + paste fields, the character rename, and the shop pill search — the last being the one most tapped on a phone), and the two raw `<input>`s never had the base at all. All six now render at 16px, and an unlayered `max(16px, 1rem)` floor in the stylesheet keeps any future small-styled field from regressing while still scaling up with larger root fonts. Viewport `maximum-scale` stays untouched so pinch-zoom keeps working
- Weekly gold shop rows no longer reset every morning: `shop::` pins (gold rows with no barter.json entry, e.g. 瓦爾特's 空瓶 at 每週 1 次) fell through the cycle lookup to the daily default, so both the local prune and the sync bucket read dropped them overnight. They now read their cycle from the deal's structured limit period — and all three cycle readers (`pinCycleOf`, `taskKind`, section placement) share that one field instead of parsing display copy. ### Fixes
- Cold boot no longer prunes before the fresh pull lands: hook-driven pulls bypass the 10s background throttle, so `checkResets` runs after a real GET instead of against a throttled no-op — on rollover boots the early prune tripped the mid-flight guard and discarded the mount pull's adopt, leaving stale state until the   next trigger (up to 60s); overlapping forced runs still serialize, and concurrent boot/focus pulls join one in-flight run instead of racing the mid-flight guard
- First paint goes fresh sooner on synced launches: `index.html` fires the session GET before the module graph loads so the round trip overlaps JS bootstrap (consume-once, id-matched, 60s TTL, live-GET fallback; the acknowledged-push overlay covers the pre-flush read, and `/api/*` matches no SW route)
- Malformed request bodies can no longer kill the dev server: `bodyOf` catches the platform JSON-parse throw (vercel dev raises instead of answering 400) and treats the body as absent, so the existing validators answer 400/404; production behavior unchanged
- Sync rebuilt on bucketed keys (store v13): every value now carries the Taipei day/week cycle it was set in, reads consider only the current cycle, and a reset prunes memory without writing anything — resets can no longer delete anything on any device, which kills the entire wipe class (late-wake tombstones, stale-tab poisoning, echo nulls, marker gating) at the root; the sync protocol no longer contains reset deletes at all
- Weekly reset no longer keeps last week's state when the rev-3 upgrade lands after a rollover: provenance-less values are now checked against the last-reset markers, and a stale marker drops them instead of stamping them current (stamping laundered Sunday's checks into Monday's bucket, where no prune could ever remove them and sync spread them to every device); upgrades with current markers and marker-less saves behave exactly as before
- Unchecking a box no longer re-checks itself after the next sync: user clears now write explicit values (uncheck → `false`, counter-zero/clear-section → `0`) instead of deleting — deletion stays silent on the wire by design (resets must not propagate), so the server's old value resurrected on every pull; explicit falses travel the ordinary value path and converge, with no tombstones and no ping-pong
- Deleting a character no longer resurrects it on the next sync: merges drop characters with no live name key (the name tombstones on delete while value keys linger till GC); `resetAll` converges the same way, and editing a custom task's kind re-stamps provenance instead of letting the next prune eat the stored check
- 每週挑戰 is now account-shared (was per-character) and 野外首領尾刀 is removed: existing progress migrates to the shared slot (best across characters, capped at 9), hides follow, and the removed id is pruned everywhere (store v14); old per-character sync keys age out on their own — nothing to re-link
- Old cycle values age out server-side via a 60-day GC (tombstoned once); v12 saves migrate silently with values untouched; pre-rev-3 devices in the same session neither see nor destroy new-format values
- Sync stops eating daily checks across devices: server PATCH was read-modify-write on one blob, so two devices pushing in the same window resolved to last-record-wins — the loser's keys vanished, pulls adopted the loss, and tombstones made it permanent (looked like focus makes the other device truth; weeklies survived only because they're tapped once). PATCH is now a single HSET on one hash per session (atomic per-field last-writer-wins); pre-hash records upgrade transparently, API shapes unchanged
- Pulls now fold the just-acknowledged push over the GET result and all sync fetches are `no-store` (client + `Cache-Control` header), so a lagged or cached read can never resurrect a pre-push absence and cascade into a wipe
- Text fields no longer trigger iOS auto-zoom on focus: `Input`/`Textarea` render at 16px instead of 14px (viewport `maximum-scale` deliberately untouched so pinch-zoom keeps working)
- Sync stops the late-wake wipe: a device opening for the first time after its peer already reset used to tombstone the peer's same-bucket checks (every morning the second device woke, the first device's dailies died). Resets now compare synced bucket markers first — late resets wipe locally but suppress tombstones and re-adopt the peer's values; link/import arrivals stamp the current bucket so they never wipe on next tick
- Sync stops the same-browser stale-tab wipe: the diff base was shared across tabs while memory is per-tab, so a suspended tab waking up diffed stale memory against another tab's fresh base and tombstoned live keys it never saw (no reset involved — markers can't catch it). Bases are now per-tab (sessionStorage, memory fallback), the shared copy only seeds tabs born later
- Sync stops deleting overflow characters: the 6-character cap slice dropped a 7th character from memory while the base kept its keys, so the next push tombstoned a character nobody removed. Pulls now scrub sliced ids from the base; their keys stay server-side and re-adopt if a slot frees
- Sync seen-markers are monotonic: a lagged or cached read can no longer walk them backward and downgrade the next catch-up reset into a full tombstoning reset (the repeated `acc:* → null` wipe pattern)
- Sync tombstones send exactly once: the diff used to re-broadcast every historical null on each push, so `null`s on the wire were mostly echoes of old deletions masking fresh ones (and bloating payloads); a null now always means a fresh deletion
